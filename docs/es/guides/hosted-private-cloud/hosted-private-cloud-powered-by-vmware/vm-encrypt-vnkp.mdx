## Objective

The aim of this guide is to explain the implementation details of **vSphere Native Key Provider** and then perform a virtual machine encryption in the OVHcloud **VMware on OVHcloud** solution.

**Find out how to implement virtual machine encryption using vSphere Native Key Provider.**

:::info
OVHcloud provides services for which you are responsible, with regard to their configuration and management. It is therefore your responsibility to ensure that they work properly.

Since 2024, OVHcloud has provided a dedicated KMS (OKMS -> OVHcloud KMS) to manage these services and the encryption of virtual machines within your VMware on OVHcloud environment. The guide [KMS for VMware on OVHcloud - VM encryption use case scenarios](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-overall-vm-encrypt/) explains the use cases and solutions available to you when using the OVHcloud KMS.

## Requirements

- You must have signed up to a [VMware on OVHcloud](https://www.ovhcloud.com/es-es/hosted-private-cloud/vmware/) solution.
- Access to the [OVHcloud Control Panel](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.es/&ovhSubsidiary=es).
- Access to the vSphere management interface.
- vSphere and hosts version 7.0 Update 2 or higher.
- The **Zerto** replication solution is not currently compatible with encryption. This means that encrypted VMs cannot be replicated.

## Presentation

**vSphere Native Key provider** allows you to encrypt virtual machines, enable vTPM in virtual machines, or enable data-at-rest encryption on vSAN, without the need for an external **KMS** (*Key Management Server*).

You can export the **vSphere Native Key provider** key and import it again on another cluster.

In detail, when encrypting a virtual machine, the ESXi host generates a **DEK** key, this key will be used to encrypt the virtual machine's files and therefore its data. The **DEK** key is encrypted using the key generated by **vSphere Native Key provider**. This encrypted DEK is stored with the virtual machine. You can find more details on **VMware** encryption by referring to the official documentation in the [Go further](#go-further) section of this guide.

### Creating a vSphere Native Key Provider

We will create the encryption key **vSphere Native Key Provider**. This key can be used to encrypt files on a virtual machine. If you want to add a virtual device **vTPM**, it is mandatory to encrypt the VM.

Log in to the **vSphere** interface. If you need help with this, please refer to our guide on Accessing the vSphere interface (/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vsphere-interface-connexion/).

Click on the root of the <code className="action">cluster</code> in the top left-hand corner, then click on the <code className="action">Configure</code> tab and choose <code className="action">Key Providers</code>.

<img className="thumbnail" alt="01 Create KEY 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key01.png" loading="lazy" />

Click the <code className="action">ADD</code> button and choose <code className="action">Add Native Key Provider</code> from the menu.

<img className="thumbnail" alt="01 Create KEY 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key02.png" loading="lazy" />

Type a name in `Name`.

:::warning
If your Private Cloud solution is older than **Premier VMware on OVHcloud**, untick the `Use key provider only with TPM protected ESXi hosts (recommended)` box.

:::


Click <code className="action">ADD KEY PROVIDER</code>.

<img className="thumbnail" alt="01 Create KEY 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key03.png" loading="lazy" />

Click the <code className="action">BACK-UP</code> button on the left to back up the key outside the cluster.

<img className="thumbnail" alt="01 Create KEY 04" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key04.png" loading="lazy" />

Select the checkbox on the left to password protect the backup.

<img className="thumbnail" alt="01 Create KEY 05" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key05.png" loading="lazy" />

Type a `password` and `confirm it`. Then select the <code className="action">I have saved the password in a secure place</code> box and click <code className="action">BACK UP KEY PROVIDER</code>.

<img className="thumbnail" alt="01 Create KEY 06" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key06.png" loading="lazy" />

The key can now be used to encrypt virtual machines.

<img className="thumbnail" alt="01 Create KEY 07" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key07.png" loading="lazy" />

### Encrypting of a virtual machine

We will encrypt a virtual machine and its data. 

:::warning
Encryption of a virtual machine can only be performed when the virtual machine is turned off.

:::


Right-click on the <code className="action">virtual machine</code> and from the <code className="action">VM Policies</code> menu choose <code className="action">Edit VM Storage Policies</code>.

<img className="thumbnail" alt="02 encrypt VM 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/02-encrypt-vm01.png" loading="lazy" />

From the `VM Storage Policies` drop-down menu, choose <code className="action">VM Encryption Policy</code> and click <code className="action">OK</code>.

<img className="thumbnail" alt="02 encrypt VM 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/02-encrypt-vm02.png" loading="lazy" />

In the virtual machine properties, click the <code className="action">Summary</code> tab. You will see a `padlock` followed by the text `Encrypted with a native key provider` indicating that the VM is encrypted. 

<img className="thumbnail" alt="02 encrypt VM 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/02-encrypt-vm03.png" loading="lazy" /> 

### Migrating an existing encryption solution to vSphere Native Key provider

Some OVHcloud customers use an encryption solution with external KMS keys. Encryption can be migrated to **vSphere Native Key Provider**.

Follow the instructions below to migrate an encrypted virtual machine with a key generated by an external KMS named **cluster** to a vSphere Native Key Provider key named **MY-NKP**.

In the **vSphere** console for your cluster, click on the <code className="action">cluster root</code> in the top left-hand corner.<br/>

Go to the top in the <code className="action">Configure</code> tab.<br/>

Click <code className="action">Key Providers</code> in the vertical bar, go to the <code className="action">vSphere Native Key provider</code> key and click <code className="action">SET AS DEFAULT</code>.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp01.png" loading="lazy" />

Confirm your choice by clicking <code className="action">SET AS DEFAULT</code>.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp02.png" loading="lazy" />

The **vSphere Native Key Provider** key is then set by default.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp03.png" loading="lazy" />

Click the <code className="action">virtual machine</code> and go to <code className="action">Summary</code> tab. This virtual machine uses the `standard key provider`. We will change the encryption of this virtual machine.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 04" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp04.png" loading="lazy" />

In the **vSphere** client, right-click on the <code className="action">virtual machine</code> that needs to be encrypted again. In the <code className="action">VM Policies</code> menu entry, choose <code className="action">Re-encrypt</code>.

:::info
The operation related to the new encryption can be done with the virtual machine turned on because only the **DEK** key is encrypted again.

:::


<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 05" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp05.png" loading="lazy" />

The new encryption takes a few milliseconds because the operation performed is only a renewal of the encryption of the **DEK** key. This key is now encrypted using the new **vSphere Native Key Provider** key.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 06" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp06.png" loading="lazy" />

Click the <code className="action">virtual machine</code> on which the encryption has been changed and go to the <code className="action">Summary</code> tab. You can see that encryption uses a native key provider next to the padlock.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 07" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp07.png" loading="lazy" />

### Encrypting a Datastore of a vSAN cluster

You can encrypt the Datastore of a vSAN cluster instead of the virtual machines.

Through your vSphere interface, go to your <code className="action">vSAN cluster</code> on the right, select the <code className="action">Configure</code> tab, scroll to **Data Services** and click <code className="action">EDIT</code>.

![Activate vSAN data at rest encryption 01](/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/04-activate-vsan-data-at-rest-encryption-01.png)

Enable <code className="action">Data-At-Rest encryption</code>, check <code className="action">Wipe residual Data</code>, choose your <code className="action">Key Provider</code> and click <code className="action">APPLY</code>.

:::info
A warning will inform you that a performance problem may occur when you enable these settings. Please ignore it.

:::


![Activate vSAN data at rest encryption 02](/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/04-activate-vsan-data-at-rest-encryption-02.png)

Go back to **Data Services** and you will see that **Data encryption at rest** is enabled with your key.

![Activate vSAN data at rest encryption 03](/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/04-activate-vsan-data-at-rest-encryption-03.png)
