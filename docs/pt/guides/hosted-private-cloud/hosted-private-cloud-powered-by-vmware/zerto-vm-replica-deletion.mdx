## Objetivo

Quando uma VM é voluntariamente eliminada do site de origem, a VPG Zerto faz uma pausa na sincronização e entra em erro.<br/>
Os ficheiros da cópia da VM ainda estão no site de destino.<br/>
Este documento mostra como apagar estes ficheiros e repor a VPG em funcionamento.

**Utilize a interface Zerto para eliminar uma cópia de VM do site alvo.**

## Requisitos

- Ter contacto com o administrador da infraestrutura [Hosted Private Cloud](https://www.ovhcloud.com/pt/enterprise/products/hosted-private-cloud/), para poder receber os dados de acesso.
- Ter um identificador de utilizador ativo com os direitos específicos para Zerto (criado na [Área de Cliente OVHcloud](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.pt/&ovhSubsidiary=pt))
- Ter implementado o [Zerto Virtual Replication](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-virtual-replication-as-a-service/)

## Instruções

Na interface Zerto do site alvo, verifique os painéis de controlo <code className="action">VPGs</code> e <code className="action">VMs</code>.<br/>
No nosso exemplo, o VPG1 contém duas VMs, vm1-zerto e vm2-zerto. O estado da sincronização do site está funcional.

<img className="thumbnail" alt="Dash" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-vm-replica-deletion/en01sync.png" loading="lazy" />

Na interface vSphere do website source, a vm2-zerto é eliminada voluntariamente.<br/>
A VM e os seus discos são apagados.

<img className="thumbnail" alt="VM" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-vm-replica-deletion/en02vmdelete.png" loading="lazy" />

De volta à interface Zerto do site alvo, a VPG faz uma pausa na sincronização e entra em erro. A VM vm2-zerto está cinzenta.

<img className="thumbnail" alt="VM" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-vm-replica-deletion/en03vpgerror.png" loading="lazy" />

No separador <code className="action">VPGs</code>, selecione VPG1 e no menu <code className="action">Actions</code>, clique em <code className="action">Edit VPG</code>.

<img className="thumbnail" alt="VPG" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-vm-replica-deletion/en04vpgedit.png" loading="lazy" />

Em <code className="action">VMs</code>, retire vm2-zerto da secção `selected VMS` (selecione a VM e clique na seta virada para a esquerda).<br/>
Clique em <code className="action">Done</code>.

<img className="thumbnail" alt="VPG" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-vm-replica-deletion/en05vpgremove.png" loading="lazy" />

Clique em <code className="action">No</code> na linha de aviso. Normalmente, não é necessário guardar o disco de recuperação.

<img className="thumbnail" alt="VPG" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-vm-replica-deletion/en06warning.png" loading="lazy" />

A VPG vai sincronizar-se de novo e tornar-se funcional com uma única VM dentro.

<img className="thumbnail" alt="DONE" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/zerto-vm-replica-deletion/en07green.png" loading="lazy" />
