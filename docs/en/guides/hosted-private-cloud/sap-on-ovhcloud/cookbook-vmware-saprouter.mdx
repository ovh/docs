## Objectif

Ce guide vous détaille le déploiement d'un SAProuter sur VMware on OVHcloud avec NSX.

## Prérequis

- Être connecté à l’[espace client OVHcloud](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.com/fr/&ovhSubsidiary=fr).
- Une solution [VMware on OVHcloud](https://www.ovhcloud.com/fr/enterprise/products/hosted-private-cloud/) avec NSX déployée dans votre compte OVHcloud.
- Un accès avec les droits de gestion pour NSX.

## En pratique

### Configuration du Network Firewall

OVHcloud propose un pare-feu paramétrable et intégré à la solution Anti-DDoS, le Network Firewall. Cette option vous permet de limiter l’exposition de votre service aux attaques provenant du réseau public. Nous vous conseillons de l'activer pour l'adresse IP publique que vous utiliserez dans cette configuration.

Si vous n'avez pas créé de Network Firewall et de règles de filtrage réseau pour l'adresse IP publique de votre gateway NSX, suivez les instructions ci-dessous pour réaliser sa mise en oeuvre. Si vous êtes familier avec le Network Firewall, vous pouvez passer à l'étape 4 dédiée à la création de la règle pour le SAProuter.

<Tabs>
  <Tab label="Étape 1">
    Connectez-vous à votre [espace client OVHcloud](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.com/fr/&ovhSubsidiary=fr), ouvrez l'onglet <code className="action">Bare Metal Cloud</code>, menu <code className="action">Network</code> puis cliquez sur <code className="action">IP</code>.
    
    Si vous possédez plusieurs adresses IP publiques ou services, vous pouvez soit filtrer avec les valeurs <code className="action">Tous les types de service</code> et sélectionner <code className="action">Hosting Private Cloud (VMware)</code>, soit avec les valeurs <code className="action">Tous les services</code> et sélectionner votre solution VMware on OVHcloud.
    
    Dans notre documentation [Premiers pas avec NSX](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-01-first-steps/), le chapitre [Affichage de l'adresse IP virtuelle HA VIP](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-01-first-steps/#displaying-the-ha-vip-virtual-ip-address/) vous présente le moyen d'obtenir votre adresse IP publique portée par votre gateway NSX.
    
    Développez votre bloc d'adresses IPv4, sélectionnez l'adresse IPv4 utilisée par votre gateway NSX et cliquez sur <code className="action">Créer Firewall</code>.
    
    <img className="thumbnail" alt="create_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/1_create_firewall.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 2">
    Cliquez sur <code className="action">Configurer le firewall</code> pour entrer en mode édition dans votre Network Firewall.
    
    <img className="thumbnail" alt="configure_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/2_configure_firewall.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 3">
    Nous vous conseillons de créer 2 règles par défaut dans votre Network Firewall.
    
    Cliquez sur <code className="action">Ajouter une règle</code> puis renseignez ces informations :
    
    1. La première règle a pour paramètres :
         - Priorité : 0
         - Action : Autoriser
         - Protocole : TCP
         - Drapeaux : ESTABLISHED
    
    Nous vous conseillons d'autoriser le protocole TCP sur toutes les adresses IP avec le drapeau `ESTABLISHED`. Cela vous permet de vérifier que le paquet fait partie d'une session précédemment ouverte/initiée. Si vous ne l'autorisez pas, le serveur ne recevra pas les retours du protocole TCP des requêtes SYN/ACK.
    
    2\. La seconde règle a pour paramètres :
    - Priorité : 19
    - Action : Refuser
    - Protocole : IPv4

    Nous vous conseillons de refuser tout trafic de protocole IPv4 qui n'a été accepté par aucune règle antérieure.
    
    <img className="thumbnail" alt="standard_rules" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/3_standard_rules.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 4">
    Créez la règle pour autoriser la connexion depuis les infrastructures du support SAP. 
    
    Cliquez sur <code className="action">Ajouter une règle</code> puis renseignez ces informations :
    
    - Priorité : 1
    - Action : Autoriser
    - Protocole : TCP
    - IP source : 194.39.131.34/32
    - Port de destination : 3299
    - Drapeaux : Aucun
    
    <img className="thumbnail" alt="create_rule" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/4_create_rule.png" loading="lazy" style={{ maxWidth: '349px' }} />

Retrouvez plus d'information sur les adresses IP publiques du support SAP sur le [site du support SAP](https://support.sap.com/en/tools/connectivity-tools/saprouter/install-saprouter.html?anchorId=section_498561288).
  </Tab>
  <Tab label="Étape 5">
    Après quelques secondes, la règle est active.
    
    <img className="thumbnail" alt="rule_3299" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/5_rule_3299.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 6">
    Cliquez sur le bouton <code className="action">Retour</code>, sélectionnez l'adresse IP où vous venez d'ajouter la règle et cliquez sur <code className="action">Activer le firewall</code>.
    
    <img className="thumbnail" alt="enable_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/6_enable_firewall.png" loading="lazy" />
  </Tab>
</Tabs>


### Configuration de la gateway NSX

La gateway NSX est la passerelle entre Internet et votre infrastructure SAP hébergée sur votre solution VMware on OVHcloud. Il est nécessaire de la configurer pour permettre la connexion du support SAP à votre infrastructure SAP via le SAProuter.

#### Firewall

Nous vous recommandons de réaliser un filtrage réseau sur votre gateway NSX, en plus du filtrage réseau réalisé via le Network Firewall précédemment effectué.

Ce filtrage réseau sur votre gateway NSX permet de sécuriser l'exposition du SAProuter en cas de désactivation du Network Firewall sur votre adresse IP publique.

<Tabs>
  <Tab label="Étape 1">
    Connectez-vous à l'interface NSX en vous rendant à l'adresse de votre solution VMware on OVHcloud, puis en cliquant sur la tuile NSX.
    
    <img className="thumbnail" alt="nsx_interface" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/1_nsx_interface.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 2">
    Cliquez sur l'onglet <code className="action">Sécurité</code>, puis dans la catégorie <code className="action">Gestion des stratégies</code>, cliquez sur <code className="action">Pare-feu de passerelle</code> et sélectionnez votre gateway T0 « ovh-T0-xxxx ».
    
    <img className="thumbnail" alt="nsx_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/2_nsx_firewall.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 3">
    Cliquez sur <code className="action">Ajouter une stratégie</code>, puis donnez lui un nom (exemple: SAP). Cette stratégie regroupera l'ensemble des règles firewall que vous pourriez avoir en lien avec SAP.
    
    Sélectionnez votre nouvelle stratégie et cliquez sur <code className="action">Ajouter une règle</code>.
    
    <img className="thumbnail" alt="nsx_firewall_policy" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/3_nsx_firewall_policy.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 4">
    Saisissez les informations suivantes :
    
    - Nom : Support SAP
    - Source : 194.39.131.34/32
    - Destination : *Adresse IP privée de votre SAProuter*
    - Service : TCP - Ports de destination : 3299
    - Action : Autoriser
    
    <img className="thumbnail" alt="nsx_firewall_rule" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/4_nsx_firewall_rule.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 5">
    Une fois la règle créée, cliquez sur <code className="action">Publier</code> afin que les modifications soient prises en compte par la gateway NSX.
  </Tab>
</Tabs>


#### NAT

Le SAProuter ne possède pas d'adresse IP publique configurée. Vous devez appliquer la configuration pour router le trafic sur le port tcp/3299 depuis l'adresse IP publique portée par votre gateway NSX vers votre SAProuter.

Pour cela, vous devez créer une règle de translation d'adresse (NAT) de destination.

Cette partie vous détaille les étapes pour créer une règle NAT de destination (DNAT) sur une gateway NSX.

<Tabs>
  <Tab label="Étape 1">
    Cliquez sur l'onglet <code className="action">Mise en réseau</code>, puis dans la catégorie <code className="action">Services réseau</code>, cliquez sur <code className="action">NAT</code>.
    
    <img className="thumbnail" alt="nsx_nat" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/1_nsx_nat.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 2">
    Sélectionnez votre gateway T0 « ovh-T0-xxxx », puis cliquez sur <code className="action">Ajouter une règle NAT</code>.
    
    Veuillez saisir ces paramètres :
    
    - Nom : SAP Support
    - Action: DNAT
    - IP source : 194.39.131.34/32
    - Adresse IP | Port de destination : *Adresse IP publique de votre gateway NSX* | 3299
    - Adresses IP traduites | Port : *Adresse IP privée de votre SAProuter* | *Vide*
    
    <img className="thumbnail" alt="nsx_nat_rule" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/2_nsx_nat_rule.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 3">
    Une fois la règle DNAT créée, cliquez sur <code className="action">Publier</code> afin que les modifications soient prises en compte par la gateway NSX.
  </Tab>
</Tabs>


À présent, le trafic provenant de l'adresse IP publique 194.39.131.34/32 détenue par SAP à destination de l'adresse IP publique de votre gateway NSX sur le port tcp/3299 sera redirigé vers votre SAProuter.

### Installation du SAProuter

Pour la réalisation de l'installation du service SAProuter sur votre machine virtuelle dédiée à cet usage, nous vous recommandons de suivre les [instructions proposées par le support SAP](https://support.sap.com/en/tools/connectivity-tools/saprouter/install-saprouter.html). Des étapes doivent être réalisées sur votre espace SAP Support LaunchPad afin de sécuriser la communication entre le support SAP et le SAProuter.

Nous vous conseillons de mettre à jour régulièrement le SAProuter et de le positionner dans un réseau surveillé et isolé du réseau de votre infrastructure SAP. Le SAProuter ne doit communiquer avec votre infrastructure SAP que sur les ports nécessaires pour le support SAP.

[Ce guide](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-06-manage-gateway-firewall/) détaille les options disponibles lors de la configuration de règles de filtrage réseau sur une gateway NSX.
