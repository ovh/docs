## Objective

This guide provides an outline of how to configure a virtual private network between an on-premises Zerto platform and an OVHcloud Managed Bare Metal.
We will use the OPNsense open-source VPN Solution as an example, and explain the simplest way to set up a VPN tunnel to the Zerto network. 

**Find out how to get started with a VPN for OVHcloud Zerto DRP.**

## Requirements

- one public IP, available on the target Managed Bare Metal for the VPN endpoint
- a Zerto platform installed on the on-premises platform
- VRAs (Virtual Replication Appliances) on both sides that are able to connect to the counterpart on TCP ports 4007 and 4008
- Zerto administration consoles or ZVMs (Zerto Virtual Managers) that are able to connect to the counterpart on TCP port 9071

## Instructions

:::info
:::

>You need to decide which network to deploy the OVHcloud ZVM in. This avoids any overlap with local networks, which would prevent routing.
>
> You can either accept the suggested network or provide your own, as long as it is within a valid /23 range.
>

### Step 1: Activate Zerto features.

It is easy to activate Zerto features from the OVHcloud Control Panel. You just need to select the datacentre linked to the Managed Bare Metal solution that you want to use, from the <code className="action">Disaster Recovery Plan</code> tab.

First select <code className="action">Between your infrastructure and an OVHcloud Managed Bare Metal</code>, then click <code className="action">Activate Zerto DRP</code>. Next, select a free public IP from the dropdown menu and enter the desired network range for the ZVM deployment. Confirm the VRA Network range and then click <code className="action">Install</code>.

### Step 3: Set up IPSec tunnel.

You can configure the IPSec tunnel by defining two sets of parameters: **Phase 1** and **Phase 2**.

##### 3.1 Set up Phase 1.

In the <code className="action">VPN</code> menu, go to <code className="action">Tunnel settings</code>, and click on the <code className="action">+</code> to add a new **Phase 1**:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-9.png" loading="lazy" />

##### 3.1.1 Phase 1: General information.

> <img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-10.png" loading="lazy" />

If the default values are correct:

- Connection Method: Default
- Key Exchange version: V2
- Internet Protocol: IPv4
- Interface: WAN

The only required parameter is the OVHcloud IPSec endpoint IP address.

##### 3.1.2 Phase 1: Authentification.

Once the default values are valid, you only need to provide the shared secret for authentication.

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-11.png" loading="lazy" />

##### 3.1.3 Phase 1: Encryption algorithms.

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-12.png" loading="lazy" />

Supported values for each parameters:

- Encryption algorithms: AES 256 bits
- Hash algorithms: SHA256
- Diffie-Hellman key group: 14 (2048 bits)
- Lifetime: 28,800 seconds

You can keep the default values for the other parameters. Click <code className="action">Save</code>, then <code className="action">Apply changes</code>.

The new Phase 1 is now present in the interface:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-13.png" loading="lazy" />

#### 3.2 Set up Phase 2.

Click on <code className="action">Show Phase 2 entries</code>.

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-14.png" loading="lazy" />

There is no phase 2 available, so you will need to add one:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-15.png" loading="lazy" />

##### 3.2.1 Phase 2: General information

Check that the mode is set to  "Tunnel IPv4".

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-17.png" loading="lazy" />

##### 3.2.2 Phase 2: Local Network

The local network type must be set to  "Lan subnet".

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-18.png" loading="lazy" />

##### 3.2.3 Phase 2: Remote Network

You need to give the ZVM IP and the associated network range.

On OVHcloud side, the ZVM network is always a /23 network (512 IPs).

:::warning

>Make sure to double-check the parameters, otherwise the VPN tunnel won't come up.

##### 3.2.4 Phase 2: Key exchange

Supported values are:

- Protocole: ESP
- Encryption algorithm: AES 256 bits
- Hash algorithms: SHA256
- PFS: Off

The tunnel is now up. Make sure to add, if required, a route to the OVHcloud ZVM network on your local ZVM.

**Troubleshooting**

If the tunnel is not coming up, make sure that the parameters values are identical on both sides:

- Shared secret
- Remote endpoint IP address
- Remote network range

Make sure that a firewall is not interfering in the dialog between the local and remote endpoints.

You can check the IPSec logfile in /var/log/ipsec.log on the OPNsense appliance to get more information.

### Step 4: Set up firewall.

To allow pairings of on-premises and OVHcloud instances, traffic must be authorised on the following ports:

* TCP 9071 between ZVMs
* TCP 4007/4008 between vRAs

#### 4.1 ZVM opening.

Go to the <code className="action">Firewall</code> menu, <code className="action">Rules</code>  section, <code className="action">IPSec</code> interface:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-25.png" loading="lazy" />

Click on <code className="action">Add</code> to create a new rule.

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-26.png" loading="lazy" />

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-27.png" loading="lazy" />

Rule parameters are as follow:

- Action: "Pass" (authorise traffic)
- Interface: "IPsec" (incoming traffic coming from the VPN tunnel)
- Protocol: "TCP"

For "Source" and "Destination", select "Single host or Network" type. The source is the OVHcloud ZVM, and the destination is your on-premises ZVM.

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-28.png" loading="lazy" />

Destination TCP port is 9071. Click <code className="action">Save</code> and <code className="action">Apply Change</code>.

#### 4.2 vRAs opening.

vRAs opening is a bit more complex since there are multiple vRAs on each side that need to be able to exchange information on TCP ports 4007 and 4008.
To simplify this setup, we are going to use the alias feature of OPNsense. An alias is a group of objects IPs, networks, URLs…) that can be used in firewall rules.

We will define three aliases:

* one for vRA IPs on the customer side
* one for vRA IPs on the OVHCloud side
* one for the ports

You can get the OVHcloud vRAs IP from the destination Managed Bare Metal vCenter interface.

Let's create the OVH_VRA alias for OVHCLoud vRAs:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-30.png" loading="lazy" />

Similarly, we can create an alias for the on-premises vRAs:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-31.png" loading="lazy" />

Finally, you need to create the ports alias:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-32.png" loading="lazy" />

#### Troubleshooting

If the on-premises ZVM is not able to successfully contact the OVHcloud ZVM (due to an incorrect firewall setup, for example) you will get the following message:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-39.png" loading="lazy" />

You will then be brought back to the log-in screen, with the following error message:

<img className="thumbnail" alt="zerto vpn" src="/images/bare-metal-cloud/managed-bare-metal/zerto-virtual-replication-customer-to-ovhcloud/image-EN-40.png" loading="lazy" />

The most probable cause is that the OVHcloud ZVM is not authorised to contact your on-premises ZVM on TCP 9071 (it needs to be able to initiate the connection).
