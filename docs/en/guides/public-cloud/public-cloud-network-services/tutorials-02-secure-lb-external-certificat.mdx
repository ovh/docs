## Objective

Our Public Cloud Load Balancer is based on [OpenStack Octavia](https://wiki.openstack.org/wiki/Octavia) and is fully integrated into the Public Cloud universe. 

After setting up your Load Balancer, you can configure it with a certificate in order to process HTTPS connections.

**This tutorial explains how to configure a secure Public Cloud Load Balancer.**

## Requirements

- A [Public Cloud project](/guides/public-cloud/public-cloud-cross-functional/create-a-public-cloud-project/) in your OVHcloud account
- [Preparing your environment for using the OpenStack API](/guides/public-cloud/public-cloud-cross-functional/prepare-the-environment-for-using-the-openstack-api/)
- [OpenStack Octavia client](https://docs.openstack.org/python-octaviaclient/latest/install/index.html) and [OpenStack Barbican](https://docs.openstack.org/python-barbicanclient/latest/install/index.html) set up
- A certificate from a third-party supplier

If you are not yet familiar with creating a Load Balancer, please follow our guide on [Getting started with Load Balancer on Public Cloud](/guides/public-cloud/public-cloud-network-services/getting-started-01-create-lb-service/) before you continue with this tutorial.

### Preparing the certificate <a name="preparingcertificate"></a>

For this stage, we need a certificate, which has already been generated. 

When your certificate is generated by your supplier, you generally receive 2 or 3 files, described as follows:

- Main certificate (.crt or .pem file).
- Private key (.key file) generated during the CSR request.
- Intermediate certificate or complete chain (.crt file), if supplied. Some suppliers already include the intermediate chain in the main certificate, in which case you will only receive 2 files.

:::warning
If you have obtained 3 files, you will need to merge the main certificate with the intermediate certificate to create a complete certificate. If your supplier already provides a complete certificate incorporating the intermediate chain, this merging step should be omitted.

:::


```bash
sudo cat <certificate.crt> <intermediate_chain.crt> > main_certificate.pem
```

You need to create a PKCS#12 package with your certificate inside:

```bash
sudo openssl pkcs12 -export -inkey <private_key.key> -in <main_certificate.pem> -out domain.tld.p12
```

You must download this file directly onto your computer in order to be able to send it to Openstack Barbican (‘Secret as a Service’).

```bash
openstack secret store --name='cert-domain.tld' -t 'application/octet-stream' -e 'base64' --payload="$(base64 < domain.tld.p12)"
```

<details>

<summary>Via the OpenStack API or via the OVHcloud Control Panel</summary>


To create a listener via the OpenStack API or via the OVHcloud Control Panel you can consult the relevant section in [this guide](/guides/public-cloud/public-cloud-network-services/getting-started-01-create-lb-service/), in the ‘Configuring your Load Balancer’ section.

Then configure the redirection of HTTP requests to HTTPS:

```bash
openstack loadbalancer l7policy create --action REDIRECT_TO_URL --redirect-url https://<your-domain-or-ip> --name redirect-to-https http-listener
```

</details>


### Configuring the secure Listener on the Load Balancer

Now that you have managed your certificate, you can add a secure Listener and associate a pool and its members with it:

<details>

<summary>Via Horizon</summary>


In the Horizon interface, open the <code className="action">Network</code> section, then click on <code className="action">Load Balancers</code>.

Select your Load Balancer by clicking on it.

You can now click on the <code className="action">Listeners</code> section, then on `Create Listener` as follows: 

<img className="thumbnail" alt="listeners list" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/loadbalancerlistenerslist.png" loading="lazy" />

**Listener Details**

<img className="thumbnail" alt="listeners https details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation1.png" loading="lazy" />

|Information|Details|
|---|---|
|Name|Specify a name for your listener.|
|Protocol|Select the TERMINATED_HTTPS protocol|
|Port|Select `443`|

**Pool Details**

<img className="thumbnail" alt="listeners https pool details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation2.png" loading="lazy" />

Under ‘Create Pool’ select <code className="action">Yes</code>.

Choose a name for your Pool, in the ‘Algortihm’ field, choose the value <code className="action">ROUND_ROBIN</code> and select <code className="action">Yes</code> under ‘TLS Enabled’.

**Pool Members**

<img className="thumbnail" alt="listeners https pool members details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation3.png" loading="lazy" />

Select the corresponding instance and click on <code className="action">Add</code>. Once this has been done, select port <code className="action">80.</code> as the ‘Port’.

**Monitor Details**

We're going to select <code className="action">No</code> as we won't be demonstrating this part in this guide.

**SSL Certificates**

<img className="thumbnail" alt="listeners https ssl details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation4.png" loading="lazy" />

Select the certificate that was previously added to Openstack Barbican, [in this section](#preparingcertificate).

Once done, click on <code className="action">Create Listener</code> to create your configured Load Balancer.

</details>


<details>

<summary>Via the OpenStack API</summary>


```bash
openstack loadbalancer listener create --protocol-port 443 --protocol TERMINATED_HTTPS --name https-listener --default-tls-container=$(openstack secret list | awk '/ cert-domain.tld / {print $2}') my_load_balancer

openstack loadbalancer pool create --name pool-tls --lb-algorithm ROUND_ROBIN --listener https-listener --protocol HTTP

openstack loadbalancer member create --subnet-id my_subnet --address <private_ip_instance> --protocol-port 80 pool-tls
```

</details>


You can now access your Load Balancer securely. However, you will need to renew your certificate. Check the renewal policy with your certificate provider.
