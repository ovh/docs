## Objective

OVHcloud Databases as-a-service (DBaaS) allows you to focus on building and deploying cloud applications while OVHcloud takes care of the database infrastructure and maintenance. 

**This guide explains how to restore a backup of a database solution in the OVHcloud Control Panel.**

We continuously improve our offers. You can follow and submit ideas to add to our roadmap at [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Requirements

- A [Public Cloud database service](https://www.ovhcloud.com/it/public-cloud/databases/) up and running

## Instructions

### Step 1: Select the database service you want to restore data from

First, you need to go to the overview page of the service you want to restore the backup from.

<img className="thumbnail" alt="Select service" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/service-selection-20230331.png" loading="lazy" />

### Step 2: Go to the backup tab

In the tab list, click on <code className="action">Backups</code>.

<img className="thumbnail" alt="Service overview" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/service-overview-20230331.png" loading="lazy" />

### Step 3: Select the backup to restore from

Select the backup from which you want to restore. To help you choose, observe the dates at which the backups have been performed in the "Creation date" column.

Click on the <code className="action">...</code> button corresponding to the chosen backup. Then click on <code className="action">Duplicate (Fork)</code> to go to the configuration page of the new service.

:::warning
The MongoDB service has the option to restore a backup in place, meaning restoring the backup on the same service. This option will rollback ALL data to the state it was in when the backup was done. This can induce data loss.

:::


<img className="thumbnail" alt="Backup tab" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/backup-tab-20230511.png" loading="lazy" />

### Step 4: Configure the target service

As seen before, when restoring a backup, you create a new separate database service on which the backup data will be imported. You are able to configure this new service as you wish.

#### Immutable options

For obvious reasons, you cannot change the engine, this option is not offered. The same goes for the engine version, you will be able to update it once the new service is running.

You will find a reminder of all these options in the order summary.

<img className="thumbnail" alt="Immutable options" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/immutable-options.png" loading="lazy" />

#### Region

You can choose a different region for your new service.

<img className="thumbnail" alt="selec tRegion" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/selectRegion.png" loading="lazy" />

#### Restore point

You have to choose a restore point from which the service will be duplicated.

##### **Backup**

The most common option is to restore from a backup.

<img className="thumbnail" alt="Restore point from backup" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/restore-point-selection-backup.png" loading="lazy" />

##### **Specific date and latest**

If your service supports point in time recovery (see [Automated Backup guide](/guides/public-cloud/public-cloud-databases/databases-05-automated-backups/) for more details), you will also be offered the option to restore from a specific date and time.

<img className="thumbnail" alt="Restore point from a specific date" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/restore-point-selection-date.png" loading="lazy" />

You will also be offered the ease to choose the most recent date directly.

<img className="thumbnail" alt="Restore point from latest" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/restore-point-selection-latest.png" loading="lazy" />

#### Plan

When restoring a backup, you can select another service plan.

<img className="thumbnail" alt="Plan selection" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/plan-selection-20230331.png" loading="lazy" />

#### Nodes

You can choose to upgrade the node to a bigger flavor.

<img className="thumbnail" alt="Node selection" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/node-selection-20230331.png" loading="lazy" />

:::info
The flavor downgrade will soon be offered. The limitation being that the targeted flavor must have enough storage to restore the backup.

:::


#### Sizing

Additional storage can be ordered while forking the service.

<img className="thumbnail" alt="Sizing selection" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/sizing-selection.png" loading="lazy" />

:::info
The storage reduction will soon be offered. The limitation being that the targeted total storage must be large enough to restore the backup.

:::


#### Options

You can update the network options.

<img className="thumbnail" alt="Options selection" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/option-selection-20230331.png" loading="lazy" />

Now click on <code className="action">Create a fork</code> and the new service will be created. Please note that depending on the backup size, it can take some time before the service is available.

### Step 5: Wait for service creation

Now all you have to do is wait for your service to be ready.
This new service is now completely independent from the one you forked the backup from. You can safely delete the old service without impacting the new one.

:::warning
The newly created service does not duplicate IP restrictions nor users which were created on the old service. You will have to recreate those before using your new service.

:::


<img className="thumbnail" alt="Forked service" src="/images/public-cloud/public-cloud-databases/databases-06-restore-backup/forked-service-20230331.png" loading="lazy" />
