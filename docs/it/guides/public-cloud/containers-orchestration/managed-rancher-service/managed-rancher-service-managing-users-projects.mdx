## Objective

Managed Rancher Service by OVHcloud provides a powerful platform for orchestrating Kubernetes clusters seamlessly. This guide will explain how to manage users and projects on your OVHcloud Managed Rancher Service.

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- An OVHcloud Managed Rancher Service (see the [creating a Managed Rancher Service](/guides/public-cloud/containers-orchestration/managed-rancher-service/managed-rancher-service-creation) guide for more information)
- An access to the Rancher UI to operate it (see the [connecting to the Rancher UI](/guides/public-cloud/containers-orchestration/managed-rancher-service/managed-rancher-service-creation) guide for more information)

## Instructions

You can manage projects, users and rights on your Managed Rancher Service by using the Rancher UI.

### Creating a new user

Log in to your Managed Rancher Service UI.

![Rancher UI Homepage](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/backup-restore-etcd-s3/rancher-ui.png)

In the menu, click on `Users & Authentication`.

![Rancher UI Homepage](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-menu.png)

A list of existing users is displayed. You should have at least a `Default Admin` user.

To create a new user, click on the `Create` button.

![Rancher UI Users](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-user.png)

Fill in the username, a new password and confirm the password. You can also optionally enter a display name and a description.

![Rancher UI SRE User](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-sre.png)

> [!warning]
>
> The password needs to have at least 12 characters.

Rancher has several levels of global permissions. If your user needs rights to create and managed new clusters, you can choose `Standard User` global permission.

![Rancher UI Standard User](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-standard-user.png)

Please refer to the official documentation to know more about [global permissions](https://ranchermanager.docs.rancher.com/how-to-guides/new-user-guides/authentication-permissions-and-global-configuration/manage-role-based-access-control-rbac/global-permissions).

Once you chose the initial permission, if you want fine-grained built-in roles, click the `Create` button.

![Rancher UI Standard Users](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-standard-user.png)

The user has been created.

### Creating a new project

A project in Rancher is a group of Kubernetes namespaces. Projects allow you to manage multiple namespaces as a group and perform Kubernetes operations in them. You can use projects to support multi-tenancy, so that a team can access a project within a cluster without having access to other projects in the same cluster.

In terms of hierarchy:

- Clusters contain projects.
- Projects contain namespaces.

In Kubernetes, features like Role-Based Access Rights (RBAC) or cluster resources are assigned to individual namespaces. A project allows you to save time by giving an individual or a team access to multiple namespaces simultaneously.

Let's create a project:

Log in to your Managed Rancher Service UI.

![Rancher UI Homepage](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/backup-restore-etcd-s3/rancher-ui.png)

Click on the name of your choosen Kubernetes cluster.

In the **Cluster** menu, click on `Projects/Namespaces`.

![Rancher UI Homepage](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/backup-restore-etcd-s3/rancher-cluster.png)

You can see that our example cluster has several existing projects: `Default` and `System`. The Default project contains the default namespace and there are several namespaces that are not in a project.

You will create a project that will contain several namespaces for a special team in your company.

Click the `Create Project` button.

Enter the name of the project then click the `Add` button to add a member to the `sre` project.

![Rancher UI Project](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-project.png)

Select the user `sre` you previously created and select the project permissions. You can select the `Member` permission if you want a user that can manage the resources inside the project but not the project itself.

![Rancher UI Project SRE](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-sre-user.png)

Then click the `Add` button to add the member to the project.

Finally, click the `Create` button to create the project.

To move the existing wanted namespaces in your `sre` project, click on the three dots button and click on `Move`.

![Rancher UI Project SRE](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-falco.png)

Select the project then click the `Move` button to move the `falco` namepace in your project.

You can do the same thing for all of the namespaces you want.

![Rancher UI Project SRE project](/images/guides/public-cloud/containers-orchestration/managed-rancher-service/managing-users-and-projects/rancher-project-ns.png)
