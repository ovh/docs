## Objective

NSX allows load balancing on a level 4 (TCP or UDP) layer or level 7 (HTTP or HTTPS) layer.

**Learn how to set up load balancing in NSX**

:::warning
OVHcloud provides services for which you are responsible, with regard to their configuration and management. It is therefore your responsibility to ensure that they work properly.

This guide is designed to assist you as much as possible with common tasks. However, we recommend contacting a [specialist provider](https://partner.ovhcloud.com/de/directory/) if you experience any difficulties or doubts when it comes to managing, using or setting up a service on a server.

## Requirements

- Being an administrative contact of your [Hosted Private Cloud infrastructure](https://www.ovhcloud.com/de/enterprise/products/hosted-private-cloud/) to receive login credentials.
- A user account with access to the [OVHcloud Control Panel](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.de/&ovhSubsidiary=de).
- Having **NSX** deployed with two segments configured in your NSX configuration, you can use this guide [Segment management in NSX](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-02-segment-management/).
- Two virtual machines with NGINX enabled on one segment.

## Instructions

We will :

- Enable Load Balancing on the gateway **ovh-T1-gw**.
- Create a server pool from two virtual machines that use a web server running on port 80.
- Add a virtual server in the Load Balancer configuration which contains our server pool.
- Set a NAT rule to redirect to the virtual server.

### Creating the tag on both virtual machines.

To simplify the administration of the Load Balancer, we will use a tag on the two virtual machines in the future server pool.

In the NSX interface go to the <code className="action">Inventory</code> tab and click on <code className="action">Virtual Machines</code> on the left.

Then click on the <code className="action">three vertical dots</code> to the left of the first virtual machine and choose <code className="action">Edit</code> from the menu.

### Virtual server creation

Your server pool is created with your two virtual machines which are members of the group. Go to the <code className="action">Virtual Servers</code> tab and click on <code className="action">ADD VIRTUAL SERVER</code>.

<img className="thumbnail" alt="06 Add virtual Server 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-09-configure-loadbalancing/06-add-virtual-server01.png" loading="lazy" />

Select <code className="action">L4 TCP</code>.

<img className="thumbnail" alt="06 Add virtual Server 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-09-configure-loadbalancing/06-add-virtual-server02.png" loading="lazy" />

Fill in this information :

- **Name** : Name of your virtual server `vs-nginx`.
- **IP Address**: Front-end IP address of your virtual server on the same network as your NGINX virtual machines `192.168.102.3`.
- **Port** : Port <code className="action">80</code>.
- **Load Balancer**: Your load balancer <code className="action">loadbalancer-on-t1</code>.
- **Server Pool**: Your server pool <code className="action">sp-nginx</code>.

Then click <code className="action">SAVE</code>.

<img className="thumbnail" alt="06 Add virtual Server 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-09-configure-loadbalancing/06-add-virtual-server03.png" loading="lazy" />

Your virtual server is active. If you connect from a machine that uses a segment on a gateway of type **Tier-1 Gateways** with this URL `http://192.168.102.3`, the Load Balancer will connect to one of the two virtual machines configured in your group.

### Adding a NAT rule

Go to <code className="action">NAT</code> in the **Network Services** section on the left and click <code className="action">ADD NAT RULE</code>.

<img className="thumbnail" alt="07 ADD DNAT TO VIRTUAL SERVER 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-09-configure-loadbalancing/07-add-dnat-to-virtual-server01.png" loading="lazy" />

Enter <code className="action">to-lb-virtual-server</code> in your rule **Name** with these options :

- **Action** : <code className="action">DNAT</code>.
- **Destination IP** : A virtual IP address of your T0 such as `198.51.100.1`.
- **Translated IP** : IP address of your virtual server `192.168.102.3`.
- **Service PORT** : Choose the predefined port <code className="action">HTTP| 80</code>.

Then click <code className="action">SAVE</code>.

<img className="thumbnail" alt="07 ADD DNAT TO VIRTUAL SERVER 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-09-configure-loadbalancing/07-add-dnat-to-virtual-server02.png" loading="lazy" />

Your rule is active. If you click on `http://virtual-ip-address-on-T0` you will be connected to your virtual server which will redirect the flow to one of the servers in your group.

<img className="thumbnail" alt="07 ADD DNAT TO VIRTUAL SERVER 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/nsx-09-configure-loadbalancing/07-add-dnat-to-virtual-server03.png" loading="lazy" />
