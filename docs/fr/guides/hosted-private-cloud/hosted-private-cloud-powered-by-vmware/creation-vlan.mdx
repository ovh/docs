## Objectif

OVHcloud installe une base de 11 VLANs sur votre vRack.

**Ce guide explique comment ajouter des VLANs supplémentaires.**

## Prérequis

- Être contact administrateur de l'infrastructure [Hosted Private Cloud](https://www.ovhcloud.com/fr/enterprise/products/hosted-private-cloud/), afin de recevoir les identifiants de connexion.
- Avoir un identifiant utilisateur actif avec les droits spécifiques pour la mise en réseau (créé dans l'[espace client OVHcloud](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.com/fr/&ovhSubsidiary=fr))

## En pratique

Dans les offres Hosted Private Cloud, les VLANs permettent d'isoler des communications privées entre les différents services OVHcloud compatibles vRack (serveur dédié, instance Public Cloud...). 

En premier lieu, rendez vous dans la vue `Mise en réseau` de votre client vSphere. Déployez le dossier **vrack** puis faites un clic droit sur le **dVS** finissant par *-vrack* et enfin cliquez sur <code className="action">Nouveau groupe de ports distribués</code>.

<img className="thumbnail" alt="New Distributed Port Group" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/08network1.png" loading="lazy" />

Nommez alors votre **Port Group** :

<img className="thumbnail" alt="nommer portgroup" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/09network2.png" loading="lazy" />

Puis configurez les paramètres recommandés par OVHcloud :

- **Liaison de port** : Statique (réservation et assignation du port à une machine virtuelle)
- **Allocation de port** : Élastique (Permet d'élargir à chaud le nombre de port)
- **Nombre de ports** : 24
- **Type de VLAN** : VLAN (les autres sont [PVLAN](https://kb.vmware.com/s/article/1010691) et Trunk)
- **ID du VLAN** : 21 (sachant que l'ID peut-être configuré de 1 à 4096)
- Cochez l'option *Personnaliser la configuration des stratégies par défaut*.

<img className="thumbnail" alt="configuration portgroup" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/10network3.png" loading="lazy" />

Vous disposez de 3 paramètres de sécurité qui peuvent être activés en fonction de votre besoin : 

- *Mode Promiscuité* (élimine tout filtrage de réception que l'adaptateur de machine virtuelle peut effectuer afin que le système d'exploitation invité reçoive tout le trafic observé sur le réseau.)
- *Modifications de l'adresse MAC* (affecte le trafic qu'une machine virtuelle reçoit. Lorsque l'option est définie sur **Accepter**, ESXi accepte les demandes de modification de l'adresse MAC effective en une adresse différente de l'adresse MAC initiale.)
- *Transmissions forgées* (affecte le trafic transmis à partir d'une machine virtuelle. Lorsque l'option est définie sur **Accepter**, ESXi ne compare pas les adresses MAC source et effective).

:::info
L'utilisation la plus fréquente de ces 3 paramètres est le CARP, notamment utilisé sur **pfSense**.

:::


<img className="thumbnail" alt="paramètres sécurité" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/11network4.png" loading="lazy" />

Nous laissons la [Formation du trafic](https://docs.vmware.com/en/VMware-vSphere/6.5/com.vmware.vsphere.networking.doc/GUID-CF01515C-8525-4424-92B5-A982489BACE2.html) désactivée.

<img className="thumbnail" alt="lissage de traffic" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/12network5.png" loading="lazy" />

En ce qui concerne le *load balacing* , selectionnez *Route basée sur le hashage IP* qui est la meilleure méthode en terme de redondance et répartition.

:::warning
Attention au niveau de la configuration de l'ordre du failover, il est nécessaire de mettre la liaison montante `lag1` en *Active* (connexion entre le réseau virtuel et le réseau physique), sinon aucune communication entre les hôtes ne sera possible.

:::


<img className="thumbnail" alt="load balancing" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/13network6.png" loading="lazy" />

Le `Netflow` est desactivé (rapport d'activité sur les flux de trafic)

<img className="thumbnail" alt="netflow" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/14network7.png" loading="lazy" />

Laissez la valeur `Bloquer tous les ports` à « Non ».

<img className="thumbnail" alt="finalisation portgroup" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/15network9.png" loading="lazy" />

Un résumé des modifications vous est alors présenté. Cliquez sur <code className="action">Terminer</code> pour confirmer la création.

<img className="thumbnail" alt="finalisation portgroup" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/16network10.png" loading="lazy" />

Nous constatons ici que le **VLAN21** est bien disponible et fonctionnel.

<img className="thumbnail" alt="vlan créé" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/17network11.png" loading="lazy" />
