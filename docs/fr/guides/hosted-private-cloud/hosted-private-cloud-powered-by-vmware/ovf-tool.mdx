## Objectif

[OVFTOOL](https://developer.broadcom.com/tools/open-virtualization-format-ovf-tool/latest) est un outil qui permet d'**exporter/importer** des machines virtuelles au format .OVF (compatible Windows, Linux et macOS).

**Ce guide est un cas d'étude de l'utilisation de cet outil**

## Prérequis

- Être contact administrateur de l'infrastructure [Hosted Private Cloud](https://www.ovhcloud.com/fr/enterprise/products/hosted-private-cloud/), afin de recevoir les identifiants de connexion.
- Avoir un identifiant utilisateur actif (créé dans l'[espace client OVHcloud](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.com/fr/&ovhSubsidiary=fr))

## En pratique

Nous utilisons l'application OVFTOOL en version 4.0 sous **Linux Debian**.

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool.png" loading="lazy" />

Pour afficher de l'aide supplémentaire par rapport à cette application, utilisez la commande `ovftool --help` ou encore `ovftool --help examples` pour obtenir des exemples de cas précis.

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool2.png" loading="lazy" />

Voici un exemple d'export d'une machine virtuelle SQL3 provenant du pcc-37-187-228-180.ovh.com au format **.ovf**.

Avant l'export, la machine virtuelle doit être éteinte. Pour cela, utilisez la commande `ovftool powerOffSource`, comme indiqué dans la capture d'écran ci-dessous.

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool5.png" loading="lazy" />

Dans les tâches récentes du vCenter, on peut constater l'arrêt de la machine virtuelle concernée.

L'export de la machine virtuelle peut maintenant être réalisé via la commande suivante :

`ovftool vi://utilisateur:password@Dedicatedcloud/datacentre/vm/lenomdevotreVM /ladestination`

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool6.png" loading="lazy" />

On peut constater que l'export s'est déroulé correctement.

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool7.png" loading="lazy" />

Si vous souhaitez convertir votre fichier .OVF au format .VMX, utilisez la commande `ovftool -tt=vmx fichier.ovf /destination/`.

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool8.png" loading="lazy" />

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool9.png" loading="lazy" />

Pour importer, il est nécessaire de connaitre le data-store de destination : `ovftool -ds=datastore fichier.ovf`

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool11.png" loading="lazy" />

La machine virtuelle est maintenant déployée dans votre infrastructure.

Enfin, la migration à froid de la machine virtuelle « SQL3 » vers une autre infrastructure Hosted Private Cloud. Le transfert est réalisé sans machine tierce.

<img className="thumbnail" alt="OVF TOOL" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/ovf-tool/ovftool14.png" loading="lazy" />
