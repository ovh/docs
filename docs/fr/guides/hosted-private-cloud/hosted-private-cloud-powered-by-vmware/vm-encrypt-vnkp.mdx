## Objectif

Ce guide a pour objectif d'expliquer les détails de la mise en œuvre de **vSphere Native Key Provider** pour ensuite effectuer un chiffrement d'une machine virtuelle dans l'offre **VMware on OVHcloud** d'OVHcloud.

**Découvrez comment mettre en œuvre le chiffrement de vos machines virtuelles à l'aide de vSphere Native Key Provider.**

:::info
OVHcloud vous met à disposition des services dont la configuration, la gestion et la responsabilité vous incombent. Il vous appartient donc de ce fait d’en assurer le bon fonctionnement.

Depuis 2024, OVHcloud met à disposition un KMS dedié (OKMS -> OVHcloud KMS) pour gérer ces services et le chiffrement de machines virtuelles au sein de votre environnement VMware on OVHcloud. Le guide [KMS for VMware on OVHcloud - Solution et cas d'usages pour chiffrer des VM](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-overall-vm-encrypt/) vous explique les cas d'usages et les solutions qui s'offrent à vous dans l'utilisation du KMS OVHcloud. 

Si vous rencontrez des difficultés, contactez votre Technical Account Manager ou rendez-vous sur [cette page](https://www.ovhcloud.com/fr/professional-services/) pour obtenir un devis et demander une analyse personnalisée de votre projet à nos experts de l’équipe Professional Services.

:::


## Prérequis

- Avoir souscrit une offre [VMware on OVHcloud](https://www.ovhcloud.com/fr/hosted-private-cloud/vmware/).
- Être connecté à votre [espace client OVHcloud](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.com/fr/&ovhSubsidiary=fr).
- Avoir accès à l’interface de gestion vSphere.
- Avoir la version de vSphere et des hôtes en version 7.0 Update 2 minimum.
- A ce jour, la solution de réplication **Zerto** n'est pas compatible avec le chiffrement. Les VMs chiffrées ne pourront donc pas être répliquées.

## Présentation

**vSphere Native Key provider** permet de chiffrer les machines virtuelles, d'activer un vTPM dans les machines virtuelles ou d'activer le chiffrement « data-at-rest » sur vSAN, sans avoir besoin d'un serveur **KMS** (*Key Management Server*) externe.

Il est possible d'exporter la clé **vSphere Native Key provider** et de la réimporter sur un autre cluster.

Dans le détail, lorsque l'on chiffre une machine virtuelle, le Vcenter génère une clé **KDK** (Key Derivation Key).<br/>
Cette clé est poussée aux ESXi et permet de générer une autre clé, la **DEK** (Data Encryption Key) qui servira à effectuer le chiffrement des fichiers composant la machine virtuelle et donc de ses données.<br/>
La clé **DEK** est chiffrée à l'aide de la **KDK**. Elle est stockée et chiffrée avec la machine virtuelle. Vous trouverez plus de détails sur le chiffrement **VMware** en consultant les documentations officielles dans la section « [Aller plus loin](#go-further) » de ce guide.

## En pratique

Il est possible que votre cluster **VMware on OVHcloud** ne soit pas en version 7.0 Update 2. Dans ce cas, [contactez le support](https://help.ovhcloud.com/csm?id=csm_get_help) pour faire évoluer votre infrastructure.

:::

### Création d'une clé vSphere Native Key Provider

Nous allons créer la clé de chiffrement **vSphere Native Key Provider**. Cette clé pourra être utilisée pour chiffrer les fichiers d'une machine virtuelle. Si vous souhaitez ajouter un périphérique virtuel **vTPM**, il est obligatoire de chiffrer la VM.

Connectez-vous à l'interface **vSphere**. Au besoin, aidez-vous du guide « [Se connecter à l'interface vSphere](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vsphere-interface-connexion/) ».

Cliquez en haut à gauche sur la racine du <code className="action">cluster</code> puis cliquez sur l'onglet <code className="action">Configurer</code> et choisissez <code className="action">Fournisseurs de clés</code>.

<img className="thumbnail" alt="01 Create KEY 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key01.png" loading="lazy" />

Cliquez sur le bouton <code className="action">Ajouter</code> et choisissez dans le menu <code className="action">Ajouter un fournisseur de clés natif</code>.

<img className="thumbnail" alt="01 Create KEY 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key02.png" loading="lazy" />

Saisissez un nom dans `Nom`.

:::warning
Si votre offre Private Cloud est plus ancienne que **Premier VMware on OVHcloud**, décochez la case `Utiliser le fournisseur de clés uniquement avec les hôtes ESXi protégés par TPM (recommandé)`.

:::


Cliquez sur <code className="action">AJOUTER UN FOURNISSEUR DE CLÉS</code>.

<img className="thumbnail" alt="01 Create KEY 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key03.png" loading="lazy" />

Cliquez sur le bouton <code className="action">SAUVEGARDE</code> à gauche pour sauvegarder la clé en dehors du cluster.

<img className="thumbnail" alt="01 Create KEY 04" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key04.png" loading="lazy" />

Cochez la case à gauche pour protéger la sauvegarde par un mot de passe.

<img className="thumbnail" alt="01 Create KEY 05" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key05.png" loading="lazy" />

Saisissez `le mot de passe` et `confirmez-le`. Cochez ensuite la case <code className="action">J'ai enregistré le mot de passe dans un lieu sûr</code> et cliquez sur <code className="action">SAUVEGARDER LE FOURNISSEUR DE CLÉS</code>.

<img className="thumbnail" alt="01 Create KEY 06" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key06.png" loading="lazy" />

Il est maintenant possible d'utiliser la clé pour chiffrer des machines virtuelles.

<img className="thumbnail" alt="01 Create KEY 07" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/01-create-key07.png" loading="lazy" />

### Chiffrement d'une machine virtuelle

Nous allons chiffrer une machine virtuelle ainsi que ses données. 

:::warning
L'opération de chiffrement d'une machine virtuelle ne peut se faire que lorsque celle-ci est éteinte.

:::


Faites un clic droit sur la <code className="action">machine virtuelle</code> puis, dans le menu <code className="action">Stratégies de VM</code>, choisissez <code className="action">Modifier les stratégies de stockage VM</code>.

<img className="thumbnail" alt="02 encrypt VM 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/02-encrypt-vm01.png" loading="lazy" />

Dans le menu déroulant `Stratégies de stockage de VM`, choisissez <code className="action">VM Encryption Policy</code> et cliquez sur <code className="action">OK</code>.

<img className="thumbnail" alt="02 encrypt VM 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/02-encrypt-vm02.png" loading="lazy" />

Dans les propriétés de la machine virtuelle, cliquez sur l'onglet <code className="action">Résumé</code>. Vous verrez apparaitre un `cadenas` suivi du texte `Chiffré avec un fournisseur de clés natif` qui indique que la machine virtuelle est chiffrée. 

<img className="thumbnail" alt="02 encrypt VM 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/02-encrypt-vm03.png" loading="lazy" /> 

### Migration d'une solution existante de chiffrement vers vSphere Native Key provider

Certains clients OVHcloud utilisent une solution de chiffrement avec des clés KMS externes. Il est possible de migrer le chiffrement vers **vSphere Native Key Provider**.

Suivez les instructions ci-dessous pour migrer une machine virtuelle chiffrée avec une clé générée par un KMS externe nommée **cluster** vers une clé vSphere Native Key Provider portant le nom **MY-NKP**.

Depuis la console **vSphere** de votre cluster, cliquez en haut à gauche sur la <code className="action">racine du cluster</code>.<br/>
Allez en haut dans l'onglet <code className="action">Configurer</code>.<br/>
Cliquez sur <code className="action">Fournisseurs de clés</code> dans la barre verticale, positionnez-vous sur la <code className="action">clé vSphere Native Key provider</code> et cliquez sur <code className="action">DÉFINIR COMME VALEUR PAR DÉFAUT</code>.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 01" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp01.png" loading="lazy" />

Confirmez votre choix en cliquant sur <code className="action">DÉFINIR COMME VALEUR PAR DÉFAUT</code>.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 02" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp02.png" loading="lazy" />

La clé **vSphere Native Key Provider** est alors définie par défaut.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 03" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp03.png" loading="lazy" />

Cliquez sur <code className="action">la machine virtuelle</code> et allez dans l'onglet <code className="action">Résumé</code>. Cette machine virtuelle utilise le `fournisseur de clés standard`. Nous allons changer le chiffrement de cette machine virtuelle.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 04" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp04.png" loading="lazy" />

Dans le client **vSphere**, faites un clic droit sur <code className="action">la machine virtuelle</code> qui doit être à nouveau chiffrée. Dans l'entrée <code className="action">VM Policies</code> du menu, choisissez <code className="action">Chiffrer à nouveau</code>.

:::info
L'opération liée au nouveau chiffrement peut se faire avec la machine virtuelle allumée, car uniquement la clé **DEK** est chiffrée à nouveau.

:::


<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 05" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp05.png" loading="lazy" />

Le nouveau chiffrement s'effectue en quelques millisecondes car l'opération effectuée n'est qu'un renouvellement du chiffrement de la clé **DEK**. Cette  clé est maintenant chiffrée à l'aide de la nouvelle clé **vSphere Native Key Provider**.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 06" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp06.png" loading="lazy" />

Cliquez sur la <code className="action">machine virtuelle</code> sur laquelle le chiffrement a été modifié et allez dans l'onglet <code className="action">Résumé</code>. Vous pouvez constater que le chiffrement utilise un fournisseur de clés natif à coté du `cadenas`.

<img className="thumbnail" alt="03 migrate-from-kms-to-vnkp 07" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/03-migrate-from-kms-to-vnkp07.png" loading="lazy" />

### Chiffrement d'un Datastore d'un cluster vSAN

Vous avez la possibilité de chiffrer le Datastore d'un cluster vSAN à la place des machines virtuelles.

Dans votre interface vSphere, positionnez-vous sur votre <code className="action">cluster vSAN</code> à droite, sélectionnez l'onglet <code className="action">Configurer</code>, faites défiler la fenêtre jusqu'à **Services de données** et cliquez sur <code className="action">Modifier</code>.

![Activate vSAN data at rest encryption 01](/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/04-activate-vsan-data-at-rest-encryption-01.png)

Activez le <code className="action">Chiffrement des données au repos</code>, cochez la case <code className="action">Effacer les données résiduelles</code>, choisissez votre <code className="action">Fournisseur de clés</code> et cliquez sur <code className="action">APPLIQUER</code>.

:::info
Un avertissement vous informe qu'un problème de performance pourrait survenir lors de l'activation de ces paramètres, n'en tenez pas compte.

:::


![Activate vSAN data at rest encryption 02](/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/04-activate-vsan-data-at-rest-encryption-02.png)

Revenez sur **Services de données** et vous constaterez que le **Chiffrement de données au repos** est activé avec votre clé.

![Activate vSAN data at rest encryption 03](/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/04-activate-vsan-data-at-rest-encryption-03.png)
