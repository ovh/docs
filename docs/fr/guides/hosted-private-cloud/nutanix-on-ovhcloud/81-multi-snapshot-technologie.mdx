## Objectif

Découvrez comment déployer et configurer **Multicloud Snapshot Technology (MST)** sur une infrastructure Nutanix on OVHcloud avec OVHcloud Object Storage.

MST permet de **répliquer les snapshots** (UVM / Volume Groups) vers des stockages **compatibles S3** pour optimiser le TCO, améliorer la mobilité des données et simplifier la reprise après sinistre (DR) via un modèle **zero-compute**.

## Vue d'ensemble & avantages

**Fonctionnalités principales :**

- Réplication périodique de snapshots vers des buckets S3<sup>1</sup> (RPO typique : 1 heure via l’infrastructure Nutanix DR).
- Modèle **Zero-Compute** : Il n'est pas nécessaire de maintenir des nœuds compute standby.
- Stockage des snapshots récents sur le cluster principal ; offload des snapshots plus anciens vers stockage objet.
- Restauration possible partout où tourne **Nutanix Cloud Platform (NCP)** : cloud, edge, on-prem.
- Intégration native avec **Prism Central** et les workflows DR existants.

**Bénéfices :**

- Réduction du TCO (réduction/pas de compute standby, stockage objet moins cher).
- Mobilité : Récupération des workloads sur différents environnements NCP.
- Simplicité d’administration via Prism.

## Prérequis

### Cluster Nutanix

- AOS 7.5.1 minimum 
- Prism Central 7.5.1 minimum

### Réseau

- Créer un **subnet dédié MST** dans Prism Element (réseau interne).
- **3 adresses IP statiques** réservées (hors plage DHCP du subnet MST).
- **4 adresses IP** depuis la plage DHCP du subnet MST (consommées par les 4 VM MST).

### Ressources VM (typique — Instance *Small*)

- 3 × **MSP Controller VM** : 10 vCPU / 24 GiB RAM chacune.
- 1 × **MSP Load Balancer VM** : 2 vCPU / 4 GiB RAM.
- **Total** : 32 vCPU et 76 GiB RAM.

### Comptes / Accès

- Compte **administrateur** de Prism Central (seul un administrateur peut déployer MST).
- Accès API / informations d'identification pour le bucket S3 avec permissions d’écriture/liste/suppression.

### Limites fonctionnelles (Instance Small)

- Jusqu'à **2000 entités protégées**.
- **75 points de restauration** par entité.
- **300 To** de données actives supportées.

### Préparer l’environnement

#### Créer le container Object Storage (Bucket)

Pour créer le container vous devez dans un premier temps créer un projet : [Créer votre premier projet Public Cloud - OVHcloud](/guides/public-cloud/public-cloud-cross-functional/create-a-public-cloud-project/).

Dans l'univers Public Cloud :

<img className="thumbnail" alt="01 Object Storage" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst1.png" loading="lazy" />

Créez un utilisateur, par exemple *admin-mst-gra* :

<img className="thumbnail" alt="02 Object Storage" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst2.png" loading="lazy" />

Notez bien les informations suivantes : 

<img className="thumbnail" alt="03 Object Storage Credentials" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst3.png" loading="lazy" />

Créez ensuite un container (bucket) : [Object Storage - Premiers pas avec Object Storage - OVHcloud](/guides/storage-and-backup/object-storage/s3-getting-started-with-object-storage/).

Dans cet exemple j'ai choisi de créer un container nommé *mst-dr-gra* à Gravelines, puisque mon cluster est Roubaix. Ceci permet d'améliorer la résilience des données.

<img className="thumbnail" alt="04 Object Storage Container" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst4.png" loading="lazy" /> 

:::info
Après avoir créé le container et l'utilisateur, vous devez être en possession de plusieurs informations importantes pour la suite :

- Le nom de votre container : dans notre exemple, *mst-dr-gra*
- L'URL de l'endpoint du container : [https://s3.gra.io.cloud.ovh.net/](https://s3.gra.io.cloud.ovh.net/)
- L'**access key**
- La **secret key**

:::


#### Activer la Market Place 

Connectez-vous à Prism Central, rendez-vous dans le centre d'administration, puis cliquez sur <code className="action">Enable Marketplace</code>.

<img className="thumbnail" alt="05 Enable Market Place" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst5.png" loading="lazy" /> 

#### Activer le Network Controller

Depuis <code className="action">Infrastructure</code>, rendez-vous dans <code className="action">Prism Central Settings</code>, cliquez sur <code className="action">Network Controller</code> puis sur <code className="action">Enable</code>.

<img className="thumbnail" alt="06 Enable Network Controller" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst6.png" loading="lazy" />

#### Créer un Subnet dédié à MST

Nous allons créer un subnet de type IPAM avec un DHCP pour l'utilisation de MST.

<img className="thumbnail" alt="07 IPAM Network" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst7.png" loading="lazy" />

#### Reconfigurer la Gateway 

Il est nécessaire de reconfigurer la gateway avec le nouveau réseau.

Ajoutez un NIC à votre VM :

<img className="thumbnail" alt="08 IPAM Network" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst8.png" loading="lazy" />

Reconfigurez ensuite votre gateway avec l'adresse IP définie dans la création du réseau IPAM.

Par exemple sur une VM Alpine :

<img className="thumbnail" alt="09 gateway setup" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst9.png" loading="lazy" />

On ajoute :

```bash
auto eth3
iface eth3 inet static
address 10.8.0.254
netmask 255.255.255.0
```

Redémarrage des services réseau :

<img className="thumbnail" alt="10 gateway setup2" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst10.png" loading="lazy" /> 

### Déployer Multicloud Snapshot Technology

1. Connectez-vous à **Prism Central** en tant qu’**administrateur**.
1. Rendez-vous dans **Admin Center → Marketplace**.
1. Dans **Nutanix Apps**, cliquez sur <code className="action">Get</code> pour **Multicloud Snapshot Technology**.

<img className="thumbnail" alt="11 get mst" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst11.png" loading="lazy" />

Sur la page d’introduction, cliquez sur <code className="action">Deploy</code>.

<img className="thumbnail" alt="12 Deploy mst" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst12.png" loading="lazy" />

Configurez ensuite l’instance MST :

- **MST Instance Size** : Sélectionnez <code className="action">Small</code> (ou une autre taille si disponible).
- **Cluster Details** : Choisissez le Prism Element cluster cible.
- **Network Configuration** : Sélectionnez le subnet MST créé.
- **Entrez les 3 IP statiques réservées** dans les champs correspondants.

<img className="thumbnail" alt="13 Deploy mst parameters" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst13.png" loading="lazy" />

- **Object Store Provider** : Sélectionnez <code className="action">S3 Compatible (Nutanix certified)</code>.
- **Object Store Endpoint** : Indiquez l'endpoint URL de votre container, dans notre exemple [https://s3.gra.io.cloud.ovh.net/](https://s3.gra.io.cloud.ovh.net/).
- **Bucket Name** : Indiquez le nom de votre container. Dans notre exemple, *mst-dr-gra*.
- **Access Key** : Indiquez l'`Access Key` de votre container.
- **Secret Key** : Indiquez la `Secret Key` de votre container.

<img className="thumbnail" alt="14 Deploy mst bucket parameters" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst14.png" loading="lazy" />

Lancez le déploiement.

<img className="thumbnail" alt="15 End of mst deployment" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst15.png" loading="lazy" /> 

## Disaster Recovery : utilisation et configuration

Une fois MST déployé et connecté à votre bucket Object Storage, vous pouvez configurer la protection et la restauration de vos workloads.

### Protection des entités

- **Étapes :**

1. Depuis **Prism Central**, accédez à **Protection Policies**, puis créez une politique de protection.

    <img className="thumbnail" alt="16 Create Protection policies" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst16.png" loading="lazy" /> 

2. Définissez le `policy name` et renseignez votre cluster dans le champ `primary location`.

    Dans le cadre `Recovery Location`, gardez Local AZ et sélectionnez le container (Bucket) précédemment configuré.

    <img className="thumbnail" alt="17 Create Protection policies" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst17.png" loading="lazy" /> 
 
3. Définissez une planification (Add Schedule) :

    - La fréquence de création de snapshots (par défaut toutes les heures).
    - Le nombre de Recovery Points à conserver localement.
    - Le nombre de Recovery Points à conserver sur le **container S3 OVHcloud**.

    <img className="thumbnail" alt="18 Define Schedule" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst18.png" loading="lazy" /> 

4. Protéger les VM :

    Selectionnez les VM à protéger puis dans le menu `action` → `data protection`, cliquez sur <code className="action">Protect</code>.

    <img className="thumbnail" alt="19 Protect VMs" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst19.png" loading="lazy" />

Selectionnez ensuite la Protection Policy précédement crée :

    <img className="thumbnail" alt="20 Protect VMs PP" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst20.png" loading="lazy" />

### Restauration

- Depuis **Prism Central → Data Protection → VM Recovery Points**, choisir un **Recovery Point** disponible dans le bucket.

<img className="thumbnail" alt="21 Select Restore Point" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/81-multi-snapshot-technologie/mst21.png" loading="lazy" />

### Cas d’usage typiques

- **Reprise après sinistre (DR)** : Perte totale du cluster source → déploiement des VM sur un autre cluster Nutanix relié au même bucket OVHcloud.
- **Migration de workloads** : Déplacer une application vers un autre site (edge ou cloud) en important les snapshots depuis le bucket.
