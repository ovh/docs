## Objectif

Notre Load Balancer Public Cloud est basé sur le service [Openstack Octavia](https://wiki.openstack.org/wiki/Octavia) et est entièrement intégré dans l'univers Public Cloud.

Une fois votre Load Balancer mis en place, vous pouvez le configurer avec un certificat afin de traiter les connexions HTTPS.

**Découvrez comment configurer un Load Balancer Public Cloud sécurisé**

## Prérequis

- Un [projet Public Cloud](/guides/public-cloud/public-cloud-cross-functional/create-a-public-cloud-project/)
- Utiliser l'environnement de commande d'Openstack ([Tutoriel](/guides/public-cloud/public-cloud-cross-functional/prepare-the-environment-for-using-the-openstack-api/))
- Avoir installé le [client Openstack Octavia](https://docs.openstack.org/python-octaviaclient/latest/install/index.html) et [Openstack Barbican](https://docs.openstack.org/python-barbicanclient/latest/install/index.html)
- Un Load Balancer actif dans votre projet
- Un certificat provenant d'un fournisseur tiers

Si vous n'êtes pas encore familier avec la création du Load Balancer, veuillez consulter notre guide « [Premiers pas avec le service Load Balancer Public Cloud](/guides/public-cloud/public-cloud-network-services/getting-started-01-create-lb-service/) » avant de poursuivre la lecture de ce guide.

## En pratique

### Attacher une adresse Floating IP à un Load Balancer

Vous trouverez les instructions pour cette partie dans cette [documentation](/guides/public-cloud/public-cloud-network-services/tutorials-01-secure-lb-letsencrypt/) dans la section portant le même nom.

### Préparation du certificat <a name="preparingcertificate"></a>

Nous aurons pour cette étape besoin d'un certificat, généré au préalable. 

Lors de la génération de votre certificat auprès de votre fournisseur, vous recevez généralement 2 ou 3 fichiers, décrits comme suit :

- Certificat principal (fichier au format .crt ou .pem).
- Clé privée (fichier .key) générée lors de la requête CSR.
- Certificat intermédiaire ou chaîne complète (fichier .crt), si fourni. Certains fournisseurs intègrent déjà la chaîne intermédiaire au certificat principal, auquel cas vous ne recevrez que 2 fichiers.

:::warning
Si vous avez obtenu 3 fichiers, il vous faudra fusionner le certificat principal avec le certificat intermédiaire pour créer un certificat complet. Si votre fournisseur fournit déjà un certificat complet intégrant la chaîne intermédiaire, cette étape de fusion doit être omise.

:::


```bash
sudo cat <certificate.crt> <intermediate_chain.crt> > main_certificate.pem
```

Vous devez créer un package PKCS#12 avec votre certificat à l'intérieur :

```bash
sudo openssl pkcs12 -export -inkey <private_key.key> -in <main_certificate.pem> -out domain.tld.p12
```

Vous devez télécharger ce fichier directement sur votre ordinateur afin de pouvoir l'envoyer dans Openstack Barbican ("Secret as a Service").

```bash
openstack secret store --name='cert-domain.tld' -t 'application/octet-stream' -e 'base64' --payload="$(base64 < domain.tld.p12)"
```

### Configurer le Load Balancer

<details>

<summary>Depuis l'interface Horizon</summary>


Dans l'[interface d'Horizon](https://horizon.cloud.ovh.net/auth/login/),  cliquez sur <code className="action">Network</code> puis sur <code className="action">Load Balancers</code>.

Sélectionnez votre Load Balancer en cliquant dessus.

Ensuite, cliquez sur l'onglet <code className="action">Listeners</code>, puis sur <code className="action">Create Listener</code> : 

<img className="thumbnail" alt="listeners list" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/loadbalancerlistenerslist.png" loading="lazy" />

**Listener Details**

<img className="thumbnail" alt="listener creation details section" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpcreation1.png" loading="lazy" />

|Information|Détails|
|---|---|
|Name|Spécifiez un nom pour votre listener|
|Protocol|Sélectionnez protocole HTTP|
|Port|Sélectionnez `80`|

**Pool Details**

<img className="thumbnail" alt="listener creation pool section" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpcreation2.png" loading="lazy" />

Sous « Create Pool », cliquez sur <code className="action">No</code>, puis en bas, cliquez sur <code className="action">Create Listener</code>.

Une fois le listener créé, cliquez dessus. Ensuite, cliquez sur l'onglet <code className="action">L7 policies</code>, puis sur <code className="action">Create L7 Policy</code>.

<img className="thumbnail" alt="l7policy creation" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerpolicieslist.png" loading="lazy" />

**L7 Policy Details**

<img className="thumbnail" alt="l7policy creation" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/l7policycreation.png" loading="lazy" />

|Information|Détails|
|---|---|
|Name|Spécifiez un nom pour la L7 Policy|
|Action|Choisissez la valeur REDIRECT_TO_URL|
|Redirect URL|Entrez son nom de domaine|

</details>


<details>

<summary>Depuis l'API OpenStack ou l'espace client OVHcloud</summary>


Pour créer un listener via l'API OpenStack ou via l'espace client OVHcloud, vous pouvez consulter la section correspondante dans [ce guide](/guides/public-cloud/public-cloud-network-services/getting-started-01-create-lb-service/), dans la section « Configurer votre Load Balancer ».

Puis configurer la redirection des requêtes HTTP vers HTTPS :

```bash
openstack loadbalancer l7policy create --action REDIRECT_TO_URL --redirect-url https://<your-domain-or-ip> --name redirect-to-https http-listener
```

</details>


### Configurer le Listener sécurisé sur le Load Balancer

Maintenant que vous avez géré votre certificat, vous pouvez ajouter un Listener sécurisé et y associer un pool et ses membres :

<details>

<summary>Depuis l'interface Horizon</summary>


Dans l'interface d'Horizon, ouvrir la section <code className="action">Network</code> puis cliquer sur <code className="action">Load Balancers</code>.

Sélectionnez votre Load Balancer en cliquant dessus.

Vous pouvez désormais cliquer sur la section <code className="action">Listeners</code>, puis sur <code className="action">Create Listener</code> comme suit : 

<img className="thumbnail" alt="listeners list" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/loadbalancerlistenerslist.png" loading="lazy" />

**Listener Details**

<img className="thumbnail" alt="listeners https details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation1.png" loading="lazy" />

|Information|Détails|
|---|---|
|Name|Spécifiez un nom pour votre listener|
|Protocol|Sélectionnez le protocole TERMINATED_HTTPS|
|Port|Sélectionnez `443`|

**Pool Details**

<img className="thumbnail" alt="listeners https pool details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation2.png" loading="lazy" />

Sous « Create Pool », sélectionnez <code className="action">Yes</code>.

|Information|Détails|
|---|---|
|Name|Spécifiez un nom pour votre Pool|
|Algorithm|Sélectionnez la valeur ROUND_ROBIN|
|TLS Enabled|Sélectionnez `Yes`|

**Pool Members**

<img className="thumbnail" alt="listeners https pool members details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation3.png" loading="lazy" />

Sélectionnez l'instance correspondante et cliquez sur <code className="action">Add</code>. Une fois cette opération effectuée, sélectionnez <code className="action">80</code> comme « Port ».

**Monitor Details**

Nous allons sélectionner <code className="action">No</code> car nous ne ferons pas la démonstration de cette partie dans ce guide.

**SSL Certificates**

<img className="thumbnail" alt="listeners https ssl details" src="/images/public-cloud/public-cloud-network-services/tutorials-02-secure-lb-external-certificat/listenerhttpscreation4.png" loading="lazy" />

Sélectionnez le certificat qui à été ajouté préalablement sur Openstack Barbican, [dans cette partie](#preparingcertificate).

Ensuite, cliquez sur <code className="action">Create Listener</code> pour créer votre Load Balancer configuré.

</details>


<details>

<summary>Depuis l'API OpenStack</summary>


```bash
openstack loadbalancer listener create --protocol-port 443 --protocol TERMINATED_HTTPS --name https-listener --default-tls-container=$(openstack secret list | awk '/ cert-domain.tld / {print $2}') my_load_balancer

openstack loadbalancer pool create --name pool-tls --lb-algorithm ROUND_ROBIN --listener https-listener --protocol HTTP

openstack loadbalancer member create --subnet-id my_subnet --address <private_ip_instance> --protocol-port 80 pool-tls
```

</details>


Vous pouvez maintenant accéder à votre Load Balancer de manière sécurisée. Attention toutefois, il faudra renouveler le certificat. Vérifiez la politique de renouvellement auprès de votre fournisseur de certificat.
