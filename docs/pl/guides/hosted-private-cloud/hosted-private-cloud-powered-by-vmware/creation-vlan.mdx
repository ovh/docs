## Objective

OVHcloud sets up a base of 11 VLANs on your vRack.

**This guide explains how to create additional VLANs.**

## Requirements

- Being an administrative contact of your [Hosted Private Cloud infrastructure](https://www.ovhcloud.com/pl/enterprise/products/hosted-private-cloud/) to receive login credentials
- A user account with access to vSphere as well as the specific rights for Networking (created in the [OVHcloud Control Panel](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.pl/&ovhSubsidiary=pl))

## Instructions

In the Hosted Private Cloud solutions, VLANs can be used to isolate private communications between different OVHcloud services that are vRack-compatible (Dedicated Server, Public Cloud instance, etc.). 

First, go to your vSphere client's <code className="action">Networking</code> view. Deploy the **vrack** folder then right-click on the **dVS** ending in *-vrack* and finally click on <code className="action">New Distributed Port Group</code>.

<img className="thumbnail" alt="New Distributed Port Group" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/08network1.png" loading="lazy" />

The next step is to name your **Port Group**:

<img className="thumbnail" alt="nominate portgroup" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/09network2.png" loading="lazy" />

Then configure the settings recommended by OVHcloud:

- **Port binding**: Static (reserving and assigning the port to a virtual machine)
- **Port allocation**: Elastic (allows the number of ports to be hot-wired)
- **Number of ports**: 24
- **VLAN type**: VLAN (the others are [PVLAN](https://kb.vmware.com/s/article/1010691) and Trunk)
- **VLAN ID**: 21 (knowing that the ID can be configured from 1 to 4096)
- Check the option *Customize default policies configuration*.

<img className="thumbnail" alt="portgroup configuration" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/10network3.png" loading="lazy" />

You have 3 security settings that can be activated according to your needs: 

- *Promiscuous mode*: eliminates any filtering that the VM adapter can perform so that the guest operating system receives all observed traffic on the network.
- *MAC address changes*: when set to **Accept**, ESXi will accept requests to change the effective MAC address to an address other than the initial MAC address.
- *Forged transmits*: affects traffic transmitted from a virtual machine. When set to **Accept**, ESXi does not compare the source and effective MAC addresses.

:::info
The most frequent use of these 3 parameters is the CARP, especially used on **pfSense**.

:::


<img className="thumbnail" alt="security settings" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/11network4.png" loading="lazy" />

Leave [Traffic shaping](https://docs.vmware.com/en/VMware-vSphere/6.5/com.vmware.vsphere.networking.doc/GUID-CF01515C-8525-4424-92B5-A982489BACE2.html) disabled.

<img className="thumbnail" alt="traffic shaping" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/12network5.png" loading="lazy" />

In terms of load balancing, select *Route Based on IP hash*, which is the best method for redundancy and load balancing.

:::warning
Be careful when configuring the failover order: It is necessary to set the `lag1` uplink to *Active* (connection between the virtual network and the physical network), otherwise no communication between the hosts will be possible.

:::


<img className="thumbnail" alt="load balancing" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/13network6.png" loading="lazy" />

The `NetFlow` is disabled (traffic flow activity report).

<img className="thumbnail" alt="netflow" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/14network7.png" loading="lazy" />

Leave the `Block All Ports` value at "No".

<img className="thumbnail" alt="portgroup finalisation" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/15network9.png" loading="lazy" />

You will then be presented with a summary of the changes. Click <code className="action">Finish</code> to confirm the creation.

<img className="thumbnail" alt="portgroup finalisation" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/16network10.png" loading="lazy" />

Here we can see that **VLAN21** is available and functional.

<img className="thumbnail" alt="vlan created" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/creation-vlan/17network11.png" loading="lazy" />
