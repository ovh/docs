## Objective

Find out how to use the power of Hyperconvergence for your virtual machines with vSAN.

**This guide explains how to set up VMware vSAN on OVHcloud Hosted Private Cloud.**

## Requirements

- Being an administrative contact of your [Hosted Private Cloud infrastructure](https://www.ovhcloud.com/pl/hosted-private-cloud/vmware/) to receive login credentials
- A user account with access to vSphere as well as the specific rights for NSX (created in the [OVHcloud Control Panel](https://www.ovh.com/auth/?onsuccess=https://manager.eu.ovhcloud.com/&from=https://www.ovh.pl/&ovhSubsidiary=pl))
- At least three vSAN hosts

:::warning
The **vSAN Data-At-Rest Encryption** and **vSAN Data-In-Transit Encryption** encryption options are not supported by default on vSAN clusters. If you would like to implement these solutions, please contact your **Technical Account Manager**.

Encryption is still possible at the VM and its data level, as described in the guide [Enabling VM Encryption with vSphere Native Key Provider](/guides/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vm-encrypt-vnkp/).

:::


## Instructions

### What is vSAN?

vSAN is an object storage solution offered by VMware. It gathers a set of disks situated directly on your VMware hosts, and presents them as a single datastore. This is known as Software-Defined Storage or SDS. One of the advantages of vSAN is that it is fully integrated into vSphere, and can be managed directly from vCenter.

For full concept review and technical specifications, check out the [Official VMware VSAN page](https://docs.vmware.com/en/VMware-vSphere/6.7/com.vmware.vsphere.vsan-planning.doc/GUID-18F531E9-FF08-49F5-9879-8E46583D4C70.html)

### Setting up vSAN

#### Turn off vSphere HA

vSAN relies on the cluster’s high-availability features. Before you start any operation, you have to ensure that you have turned it off.

In the vSphere interface menu, go to the <code className="action">Hosts and Clusters</code> dashboard.

<img className="thumbnail" alt="Menu" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en01hosts.png" loading="lazy" />

On the left side, select your cluster, go in the <code className="action">Configure</code> tab then <code className="action">vSphere Availability</code>.<br/>
Click the <code className="action">Edit</code> button.

<img className="thumbnail" alt="Menu" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en02cluster.png" loading="lazy" />

Turn off vSphere HA and click <code className="action">OK</code>.

<img className="thumbnail" alt="HA" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en03ha.png" loading="lazy" />

#### Turn on vSAN Service

In the Cluster configuration menu, go down to <code className="action">vSAN</code> / <code className="action">Services</code> and click on <code className="action">Configure</code>.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en04vsan.png" loading="lazy" />

This guide is based on vSAN’s essential features so we will be using the default options.<br/>
All of our hosts are on the same site. We'll select `Single site cluster` and click <code className="action">Next</code>.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en05vsantype.png" loading="lazy" />

You can enable `Deduplication and compression` to optimize storage space.<br/>

However, lower performance and increased latency may be observed in some cases, especially when using databases.

Click <code className="action">Next</code>.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en06vsanservices.png" loading="lazy" />

The Claim disks window assigns available disks to cache or capacity (see [Official VMware VSAN page](https://docs.vmware.com/en/VMware-vSphere/6.7/com.vmware.vsphere.vsan-planning.doc/GUID-18F531E9-FF08-49F5-9879-8E46583D4C70.html) for explanation) depending on types and sizes. You can customize it to your need.<br/>
Click <code className="action">Next</code>.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en07vsanclaim.png" loading="lazy" />

With three hosts, fault domain is set up automatically and a single failure will be tolerated.<br/>
Click <code className="action">Next</code>.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en08vsanfault.png" loading="lazy" />

Verify the settings in the summary window, then click <code className="action">Finish</code>.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en09vsanready.png" loading="lazy" />

Go back to the cluster configuration and turn vSphere HA back on.<br/>
Your datastore is visible in the storage section and available to use.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en10vsandata.png" loading="lazy" />

:::warning
For performance and resilience reasons, VMware recommends not using more than 70% of the volume of a vSAN datastore.

:::


### Turn off vSAN

Before turning off vSAN, make sure to evacuate all of the virtual machines hosted on the datastore, or delete the machines you are no longer using.
Click on the ‘Datastore’ tab, and check that there are no virtual machines set up on the vSAN datastore.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en11vsanvm.png" loading="lazy" />

#### Delete disk groups.

To delete all of the vSAN configuration details for your disks, you need to delete the group of disks created by vSAN when you turned it on.<br/>
In the Cluster configuration menu, go down to <code className="action">vSAN</code> / <code className="action">Disk Management</code>.<br/>
For each disk group, click on <code className="action">...</code> then <code className="action">Remove</code>.<br/>

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en12vsanremove.png" loading="lazy" />

You are given the option to migrate data. With an empty datastore, there is No data migration necessary.<br/>
Click on <code className="action">Remove</code>.

<img className="thumbnail" alt="VSAN" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en13vsanmig.png" loading="lazy" />

Repeat for each of the nodes in the cluster, until the entire disk group has been cleared.<br/>
You can safely ignore  error messages regarding the health of the disk group.

#### Turn off Services.

The same way you turned off the high-availability feature to set up vSAN, you will need to turn it off before you stop vSAN.

<img className="thumbnail" alt="HA" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en03ha.png" loading="lazy" />

Once high-availability has been turned off, you can stop the vSAN service in the cluster properties by clicking <code className="action">Turn Off vSAN</code>

<img className="thumbnail" alt="SERVICE" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en14vsanoff.png" loading="lazy" />

Confirm by clicking ‘Turn Off’ in the next window.

<img className="thumbnail" alt="SERVICE" src="/images/hosted-private-cloud/hosted-private-cloud-powered-by-vmware/vmware-vsan/en15vsanconfirm.png" loading="lazy" />

vSAN is now off.
